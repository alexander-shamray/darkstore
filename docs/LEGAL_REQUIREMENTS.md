## 1. Юридическое лицо

### 1.1 Выбор организационно-правовой формы

| Форма | Преимущества | Недостатки |
|-------|-------------|-----------|
| **ИП** | Простая регистрация, малый налог (3% с оборота или 1% + НДС), нет корпоративного управления | Личная ответственность, сложнее привлекать инвестиции |
| **ТОО** | Ограниченная ответственность (только уставный капитал), лучше для инвесторов | Сложнее открыть, КПН 20% с прибыли |

**Рекомендация для MVP:** ИП по упрощённой декларации (форма 910) — быстрая недорогая регистрация. Перейти на ТОО при обороте > 24 038 МРП (~90 млн тг в 2026 году) или при привлечении внешних инвестиций.

**Чеклист:**
- [ ] Зарегистрировать ИП / ТОО через [egov.kz](https://egov.kz) или ЦОН
- [ ] Получить БИН/ИИН
- [ ] Открыть расчётный счёт (Kaspi Bank / Halyk / Forte — с приоритетом Kaspi Pay)
- [ ] Встать на налоговый учёт

## 2. ОФД — онлайн фискальный доступ

### 2.1 Требование

По Налоговому кодексу РК (ст. 166, 167), все продавцы товаров обязаны применять **контрольно-кассовую машину (ККМ)** с передачей данных в **ОФД КНП**. Это касается интернет-торговли.

### 2.2 Варианты

**Вариант A: Kaspi Pay закрывает вопрос (рекомендуется)**
- Kaspi Pay умеет отправлять электронный чек в ОФД
- При оплате через Kaspi — ОФД выполняется автоматически
- Нужно уточнить у менеджера Kaspi Мерчант
- **Наименее трудоёмкий вариант**

**Вариант B: Отдельная ОФД-система**
- OFD.kz — один из ведущих операторов
- Нужна интеграция с кассовой ПО (программное или аппаратное)
- Стоимость услуг ОФД-оператора

**Чеклист:**
- [ ] До запуска — уточнить: включает ли Kaspi Pay ОФД-отчётность или требуется отдельная система
- [ ] Для других способов оплаты — установить отдельную ОФД для пробития чеков
- [ ] Зарегистрировать в уполномоченном ОФД органе после выбора оператора

## 3. Закон «О персональных данных и их защите» №94-V

### 3.1 Статус соответствия требованиям

В **архитектуре системы (уже заложено):**
- База KZ Local DB — `PersonalDataDbContext`: Users, Addresses, LoyaltyTransactions, Notifications, CourierProfiles, RefreshTokens, OtpCodes
- В Azure SQL (Sweden Central) — `AppDbContext`: бизнес-данные без ПДн

### 3.2 Открытые вопросы для юриста

- [ ] По **локализации серверов данных:** допускает ли регулятор хранение **только KZ Local DB** в Azure (Sweden Central), или данные обязательно должны быть физически в Казахстане
- [ ] По **передаче ПДн через API:** API-сервер в Azure (Sweden Central) запрашивает ПДн из KZ DB при авторизации — является ли это «трансграничной передачей данных»?
- [ ] По **обработке ПДн сотрудников:** нужно ли Dark Store регистрироваться как оператор ПДн в реестре
- [ ] По **требованию уведомления:** обязан ли оператор ПДн уведомить уполномоченный орган
- [ ] По **согласию пользователей:** достаточно ли галочки «согласен с ПП» при регистрации

### 3.3 Документы для пользователей (обязательно до запуска)

- [ ] Составить Политику конфиденциальности (Privacy Policy)
- [ ] Пользовательское соглашение (Terms of Service)
- [ ] Форма сбора согласия на обработку ПДн (ст. 24 Закона №94-V)

## 4. Трудовое законодательство

### 4.1 Варианты оформления

| Статус | Описание | Налоги | Риски |
|--------|---------|--------|-------|
| **Штатный курьер** | Трудовой договор ИП/ТОО | ИПН 10%, ОПВ 10%, ОСМС 2%, СО — итого ~13.5% | Обязательный отпуск, больничные, сложное увольнение |
| **Курьер ГПХ** | Договор подряда, не работник | ИПН 10%, ОПВ 10% (ГПХ), ОСМС 1.5% (ГПХ) | Нельзя для регулярного труда — налоговые риски |
| **ИП-курьер** | Курьер — самозанятый ИП | Сам платит налоги (1-3%) | Без гарантий, легко прекратить сотрудничество |

**Рекомендация на MVP:** курьеры как ИП или ГПХ.

**Чеклист:**
- [ ] До запуска — выяснить правовой статус курьера с точки зрения ТК РК в данной бизнес-модели
- [ ] Подготовить шаблон договора с курьерами и сборщиками
- [ ] Определить систему выплат (например: X тг за смену + Y тг за доставку)

## 5. Санитарные требования (СанПиН) для склада

### 5.1 Основные требования

| Требование | Кем проверяется | Статус |
|-----------|---------|--------|
| Санитарно-эпидемиологическое заключение (СЭЗ) на склад | Обязательно при хранении продуктов | ❌ Не получено |
| Температурный режим: ambient (+15..+25°C), chilled (+2..+6°C), frozen (-18°C) | ККОМ / Роспотребнадзор | ❌ Не реализовано |
| Маркировка и этикетирование (в т.ч. дата изготовления) | Обязательно | ❌ Не готово |
| Журнал контроля сроков годности продуктов (ежедневно) | Самостоятельный учёт | ❌ Не готово |
| Санитарные книжки у сотрудников | Выдаётся в аккредитованном учреждении | ❌ Не оформлено |

**Чеклист:**
- [ ] До открытия склада — проконсультироваться с органом СЭС (СанКНП) для получения СЭЗ
- [ ] Согласовать требования к системам хранения с учётом холодного склада
- [ ] Завести журналы контроля сроков годности у операционного менеджера
